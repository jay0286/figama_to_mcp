# Git 커밋 명령

변경사항을 확인하고 컨벤션에 맞게 커밋을 생성합니다.

## 커밋 컨벤션

### 메시지 형식
```
<type>: <subject>

<body (optional)>
```

### Type 종류
- `feat`: 새 기능 추가
- `fix`: 버그 수정
- `docs`: 문서 변경
- `style`: 코드 포맷팅 (기능 변경 없음)
- `refactor`: 리팩토링
- `test`: 테스트 추가/수정
- `chore`: 빌드, 설정, 의존성 변경
- `deploy`: 배포 관련

### 규칙
- subject는 50자 이내, 명령형으로 작성
- body는 변경 이유와 내용을 간결하게 설명 (한글 OK)
- 커밋 메시지 끝에 Claude Code 서명 추가

## 실행 절차

1. `git status`와 `git diff --stat`으로 변경사항 확인
2. 변경사항이 많을 경우, 연관이 있는 변경사항들만 모아서 순차적으로 스테이징과 커밋을 진행한다.
3. gh cli로 현재 오픈된 이슈들을 확인한다.
    - 현재 변경사항 관련 이슈가 있을 경우, 이슈 번호를 커밋 메시지에 추가한다.
    - 관련 이슈가 없을 경우, 이슈를 생성하고 생성된 이슈 번호를 커밋 메시지에 추가한다.
4. 변경 내용을 분석하여 적절한 type 선택
5. 클로드 코드 메시지 제외하고 커밋 메시지 작성 후 수정가능한 방식 사용자에게 초안을 제공한다.
6. 사용자 확인 필요시 수정 후 커밋 실행

## 커밋 메시지 예시

```
feat: Add game list UI component

게임 목록을 그리드 형태로 표시하는 GameListPage 추가
- Firestore에서 games 컬렉션 조회
- 썸네일 이미지 로딩 처리

```
